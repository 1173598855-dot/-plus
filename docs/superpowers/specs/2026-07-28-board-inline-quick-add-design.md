# 看板列内快速新建设计

## 目标

让用户在看板中无需离开当前状态列即可捕捉一个仅含标题的任务，同时保留左侧完整快速新建表单用于补充优先级、日期、项目等字段。

## 交互方案

- 每个未筛选的看板状态列在任务列表后显示一个紧凑新建表单。
- 表单包含一个标题输入框和一个 Lucide `Plus` 图标按钮；按 `Enter` 或点击按钮都会创建任务。
- 输入会先去除首尾空白。空白标题不创建任务，按钮保持禁用。
- 每列维护独立草稿；成功创建后只清空当前列，其他列中尚未提交的文字不受影响。
- 中文输入法仍在组合文字时，`Enter` 不提交表单。
- 新任务使用现有 `createTask` 领域函数，状态取目标列，其他字段沿用领域默认值；在“已完成”列创建时由领域函数写入 `completedAt`。
- 新任务追加到目标列现有任务之后，设为当前选中任务，但不自动打开详情抽屉。
- 状态区域显示 `已在<状态>创建任务“<标题>”。`；任务状态变化继续通过现有 localStorage effect 持久化。

## 筛选行为

启用任意筛选、搜索或“隐藏已完成任务”时，不显示列内快速新建表单。原因是仅含标题的新任务无法可靠继承日期、项目、标签和搜索语义，创建后可能立即从当前结果中消失。此时用户仍可使用左侧完整快速新建表单；清空筛选后列内入口恢复。

## 组件与数据流

- `TaskViews` 持有五个临时列标题草稿，并通过 `onAddTaskToColumn(title, status)` 上报提交。
- `TaskWorkspace` 继续作为任务状态唯一所有者，调用 `createTask`、更新 `tasks`、设置 `selectedId` 和可访问状态消息。
- 新增界面文案集中在 `taskUiText.ts`，组件不内联新增中文字符串。
- 不修改任务模型、备份格式、存储键、拖拽、批量操作或详情抽屉状态机。

## 视觉与响应式

- 沿用现有克制的工作台样式，不新增卡片层级、阴影、渐变或依赖。
- 新建表单紧跟任务栈并保留 `12px` 间距；输入和按钮使用现有边框、圆角、焦点环与语义色。
- 输入和按钮在桌面及移动端都至少 `40px` 高；移动端看板仍为单列且无页面横向溢出。
- 保留已验收的全高工作台契约：`.workspace` 和 `.rail` 使用 `100dvh`，看板列占满剩余工作区，移动详情层使用 `100dvh`。

## 可访问性

- 每列表单、标题输入和提交按钮都有包含状态名称的唯一可访问名称。
- 禁用状态由原生 `disabled` 暴露；表单使用原生提交语义。
- 键盘焦点使用既有焦点环，创建后焦点留在当前列输入框，便于连续捕捉。

## 验收

- `Enter` 与按钮均能在正确状态列创建任务并持久化。
- 已完成列任务包含完成时间；标题被 trim；空白标题和输入法组合回车不提交。
- 提交一列不会清空另一列草稿；创建后当前输入框保持焦点。
- 筛选启用时入口隐藏，清空后恢复。
- 全高工作台、侧栏滚动、移动触控尺寸与无横向溢出契约不回归。
- `npm test`、`npm run build`、`git diff --check` 和桌面/移动浏览器验收通过。

## 范围外

- 不在列内编辑优先级、日期、项目、标签或备注。
- 不让新任务自动继承筛选条件。
- 不改变全局 `n` 快捷键、左侧快速新建表单或任务排序规则。
